# 카테고리·판매자 분석 기간 coverage 감사

감사일: 2026-11-11 (Asia/Seoul)

## 1. 목적과 범위

카테고리·판매자 월별 분석에서 희소한 초기 구간이나 데이터 종료 영향을 정상적인
월간 변화로 오해하지 않도록 주 분석 기간을 정하기 위한 읽기 전용 감사다.

같은 PostgreSQL `repeatable read`, `read only` transaction에서 다음을 확인했다.

- raw와 staging 주문의 구매 timestamp 범위와 행 수
- 월별 전체 주문과 delivered 주문 수
- 월별 전체 주문상품 행과 delivered 주문상품 행 수
- 첫·마지막 후보 구간의 실제 관찰 날짜와 일별 건수
- 제안 기간에서 category·seller mart의 가산 지표 대사

이 감사는 원천이 현실의 모든 주문을 빠짐없이 담았다는 사실을 증명하지 않는다.
현재 snapshot 안에서 월별 비교에 불리한 coverage 경계를 찾는 절차다.

## 2. 확인된 원천 범위

| 항목 | 결과 |
|---|---:|
| raw 주문 행 수 | 99,441 |
| staging 주문 행 수 | 99,441 |
| 최초 구매 timestamp | 2016-09-04 21:15:19 |
| 최종 구매 timestamp | 2018-10-17 17:30:18 |

raw와 staging의 주문 행 수와 최소·최대 구매 timestamp는 같았다. timestamp 변환 과정에서
관찰 범위가 줄지 않았다는 뜻이지, snapshot 바깥 기간까지 포함한다는 뜻은 아니다.

구매가 1월 5일부터 관찰돼 달력 월 전체가 아니다. 2017년 2월부터는 모든 달력 날짜에

종료 또는 배송 완료 관찰기간 부족의 영향을 먼저 의심하는 편이 안전하다.

## 4. 제안하는 비교 기간

주 분석 기간은 **2017-02부터 2018-07까지 18개월**로 제안한다.

- 시작 월부터 달력 날짜 전체가 관찰된다.
- 중간에 빠진 월 없이 연속된다.
- 마지막 월까지 월말 주문과 delivered 주문이 안정적으로 관찰된다.
- 희소 초기 구간과 종료 영향이 의심되는 2018-08 이후를 월별 증감에서 분리한다.

2016-09~2017-01과 2018-08은 원천 범위를 숨기지 않기 위해 참고 구간으로 남기되,
Top 5 선정과 월별 변화 결론에는 사용하지 않는 것을 제안한다. 2018-09~10은 delivered
거래 mart 모집단이 없으므로 카테고리·판매자 분석 대상이 아니다.

두 mart의 주 분석 기간 모집단과 가산 지표는 정확히 일치했다. 이 기간은 전체 delivered
주문상품 110,197행 중 101,825행을 포함한다. 제외 구간을 숨기지 않고 보고서와
dashboard에 전체 snapshot 범위와 주 분석 기간을 함께 표시해야 한다.

## 6. 해석 한계

- 관찰 날짜가 모두 있다는 사실만으로 외부 시스템에서 모든 주문이 수집됐다고 증명할
  수 없다.
- delivered 상태는 구매 시점 이후의 관찰기간 영향을 받으므로 snapshot 끝부분에서
  특히 보수적으로 해석해야 한다.
- 제안 기간은 월별 구성과 집중도를 비교하기 위한 분석 선택이며 회계·운영 기간이 아니다.
- 기간을 정한 뒤에도 월별 변화는 원인을 증명하지 않는다.

## 7. 재현·검증 방법

로컬 PostgreSQL의 기존 raw·staging·fact·mart를 변경하지 않고 다음 조건으로 집계했다.

```sql
begin transaction isolation level repeatable read read only;

-- raw/staging 최소·최대 구매 timestamp와 행 수
-- 구매월별 전체·delivered 주문 수
-- 구매월별 전체·delivered 주문상품 행 수
-- 첫·마지막 후보 구간의 일별 주문 수
-- 2017-02-01 이상, 2018-08-01 미만인 두 거래 mart의 가산 지표

commit;
```

실행 중 table·row를 수정하거나 분석 mart를 다시 build하지 않았다.

2026-11-12 다음 결정을 승인했다.

1. 주 분석 기간을 2017-02~2018-07로 사용한다.
2. 2016-09~2017-01과 2018-08은 참고 구간으로만 표시한다.
3. 승인 기간으로 Top 5 category를 선정하고 월별 변화 기여를 계산한다.

분석 계약에 이 기간을 반영했으며, 이후 pandas 구현은 이 모집단과 경계 정책을 따른다.
